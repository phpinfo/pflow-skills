# vektra/mockery — generated mocks

## Setup (v3, current)

- Config `.mockery.yml` at the module root; no `//go:generate` comments needed:

```yaml
all: false
dir: '{{.InterfaceDir}}/mocks'          # or a central "internal/mocks"
pkgname: mocks
filename: 'mock_{{.InterfaceName | snakecase}}.go'
structname: 'Mock{{.InterfaceName}}'
template: testify                       # testify | matryer | custom
force-file-write: true
packages:
  github.com/acme/tool/internal/storage:
    config:
      all: true                          # every interface in the package
  github.com/acme/tool/internal/usecase:
    interfaces:
      Clock: {}
      Notifier: {}
```

- Install as a module tool (`go get -tool github.com/vektra/mockery/v3@v3` on Go 1.24+) and run `go tool mockery`; or pin the binary version in the task runner. Never rely on a random global install — generated output differs between versions.
- Add a `mocks`/`generate` task (`task mocks` / `make mocks`) and a CI check that regenerating produces no diff.
- Commit generated mocks; mark them generated (mockery already writes `// Code generated by mockery`). Never hand-edit.
- v2 legacy: `//go:generate mockery --name=Store --with-expecter` per interface or `.mockery.yaml` with `with-expecter: true`; migration to v3: config keys are renamed (`inpackage`→`inpackage`, `outpkg`→`pkgname`, `mockname`→`structname`), `with-expecter` is always on, `all` moved under packages.

## Using the mocks

```go
store := mocks.NewStore(t)                       // registers AssertExpectations in t.Cleanup
store.EXPECT().Get(mock.Anything, "u1").Return(user, nil).Once()
store.EXPECT().Save(mock.Anything, mock.MatchedBy(func(u User) bool { return u.ID == "u1" })).
    RunAndReturn(func(_ context.Context, u User) error { saved = u; return nil })

svc := NewService(store, mocks.NewClock(t))
```

- Always use the constructor `NewX(t)`; a bare `&mocks.X{}` skips expectation verification and the panic-on-unexpected-call behavior.
- Prefer the typed `EXPECT()` API over string `On("Method", …)` — refactors stay compile-checked.
- `mock.Anything` for `ctx`; exact values for everything you care about; `MatchedBy` for partial matching. Assert call counts with `.Once()`/`.Times(n)`; `.Maybe()` for calls the test doesn't care about.
- Unexpected calls fail the test with a panic listing the expectations — read it; don't loosen matchers to silence it.
- Return errors with sentinels (`Return(nil, ErrNotFound)`) so the code under test can `errors.Is`.
- Order-sensitive flows: `mock.InOrder(call1, call2)` (testify ≥ 1.9) or record a slice in `Run`.

## When to mock

- Boundaries only: repositories, external clients, clock, filesystem, message bus. Never mock the struct under test, value types, or stdlib interfaces you can fake trivially (`io.Reader` → `strings.NewReader`).
- Interface belongs to the consumer package; generate the mock next to it (`internal/usecase/mocks`) or in a shared `internal/mocks` when many packages share it.
- If a test needs > 4–5 expectations on one mock, the unit is too big or the interface too wide — split before writing more mocks.
- Prefer a real in-memory implementation (fake) when behavior matters across many tests (an in-memory `Store`); use mocks for interaction checks and error injection.
- Don't mock in integration tests; use real dependencies (testcontainers) behind a build tag.

## Gotchas

- Generic interfaces are supported; instantiate the mock with type arguments (`mocks.NewRepo[User](t)`).
- Variadic methods: match with explicit args or `mock.Anything` per element; `unroll-variadic: false` config to receive them as a slice.
- Changing an interface without regenerating yields compile errors in tests — good; run `mockery` first, then fix tests.
- Mocks embed `mock.Mock`; don't copy them by value.
